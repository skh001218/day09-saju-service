# 📋 기획서 (PRD) : 처음 만나는 쉬운 사주

> 사주를 처음 접하는 사람이 계산 결과와 자세한 해석을 쉬운 말로 이해하고 다시 볼 수 있도록 돕는 웹 서비스입니다.

작성일: 2026-09-23  
작성자: 참가자와 Codex

---

## 1. 풀고자 하는 문제

- **지금은 이렇게 해요:** 생년월일과 출생시간을 입력하면 년주·월주·일주·시주와 일간이 표시됩니다.
- **이게 불편해요:** 사주를 처음 보는 사람은 계산 결과가 자신에게 어떤 의미인지 이해하기 어렵습니다.
- **이렇게 되면 좋겠어요:** 계산 결과와 함께 자신의 기본 성향을 전문용어 없이 한 문장으로 바로 이해할 수 있으면 좋겠습니다.

## 2. 사용자

- **누가 쓰나요?** 사주를 처음 접하는 사람
- **언제 쓰나요?** 자신의 사주와 기본 성향이 궁금할 때
- **어디서 쓰나요?** 휴대전화나 컴퓨터의 웹 브라우저

## 3. 입력 자료

- **입력 내용:** 양력 생년월일과 출생시간
- **반드시 필요한 항목:** 생년월일, 출생시간
- **개인정보 포함 여부:** 생년월일과 출생시간은 개인 정보가 될 수 있습니다. 2단계에서는 입력값과 결과를 현재 브라우저의 `localStorage`에 저장합니다. 해석 요청 시 서비스 서버로 입력값이 전달되며, Gemini에는 계산된 사주 정보만 전달합니다.
- **현재 제한:** 1990년 1월 1일부터 한국 시간 기준 오늘까지의 양력 날짜와 출생시간을 아는 경우만 지원합니다.

## 4. 핵심 기능 (MVP)

1. 양력 생년월일과 출생시간을 입력할 수 있습니다.
2. 입력값으로 년주·월주·일주·시주를 계산합니다.
3. 기존 사주 네 기둥과 일간을 결과 화면에 표시합니다.
4. 이미 계산된 일간의 오행(목·화·토·금·수)에 맞춰 미리 작성한 쉬운 성향 문장 하나를 표시합니다.
5. 값이 비었거나 지원하지 않는 입력이면 확인할 내용을 쉬운 말로 안내합니다.

- **AI에게 맡길 것:** 사용자가 별도 버튼을 눌렀을 때 성향·강점·주의점에 대한 짧은 해석을 작성합니다. 사주 계산은 기존 코드가 수행합니다.
- **사람이 확인할 것:** 해석이 이해하기 쉽고 단정적이거나 불안감을 주는 표현이 아닌지 확인합니다.

## 5. 결과와 완료 조건

- **결과물과 위치:** `day09/`에서 실행되는 기존 Next.js 웹 화면
- **정상 결과:** 유효한 생년월일과 출생시간을 입력하고 버튼을 누르면 사주 네 기둥, 일간과 함께 쉬운 성향 한 문장이 보입니다.
- **예시:** 일간 오행이 `토`이면 “차분하게 중심을 잡고, 맡은 일을 꾸준히 밀고 나가는 성향이 돋보여요.”와 같은 한 문장이 보입니다. 정확한 다섯 문구는 기능 명세에서 확정합니다.
- **실패 결과:** 값이 없거나 지원하지 않는 날짜·시간이면 결과 대신 수정할 항목을 알려주는 안내가 보입니다.
- **완료 판단:** 자동 테스트를 통과하고 브라우저에서 계산, Gemini 해석, 오류·재시도, 여러 결과의 저장·다시 열기·삭제를 확인합니다.

## 6. 이번 범위에서 제외하거나 나중에 추가할 것

- 결제 및 전문가 상담 연결은 제외합니다.
- 2단계의 성향·강점·주의점 해석보다 더 긴 심층 풀이
- 두 사람의 사주를 비교하는 궁합, 진로, 재물, 건강 해석
- 매일·매월·매년 운세
- 로그인과 다른 기기 간 결과 동기화(2단계까지 제외, 3단계에서 추가)
- 대화형 AI 상담
- 음력, 출생시간 모름, 1990년 이전 날짜 지원

## 11. 2단계 목표: Gemini 해석과 결과 보관

- **사용자 경험:** 먼저 기존 사주 네 기둥과 기본 성향 한 문장을 보여줍니다. 사용자가 **자세히 해석하기**를 누르면 Gemini가 성향·강점·주의점을 각각 짧고 쉬운 한국어로 설명합니다.
- **결과 보관:** 생년월일, 출생시간, 계산 결과, 세 부분의 해석을 현재 브라우저의 `localStorage`에 여러 건 저장합니다. 목록에서 다시 열고 개별 삭제할 수 있습니다. 같은 브라우저를 쓰는 다른 사람에게 기록이 보일 수 있음을 안내합니다.
- **실패 조건:** 입력 오류에는 Gemini를 호출하지 않습니다. 키 누락, 호출 실패, 잘못된 응답에서는 기존 계산 결과를 유지하고 오류와 재시도 방법을 보여줍니다. 가짜 해석은 만들지 않습니다. 저장 실패 시 해석은 보여주되 저장 실패를 알립니다.
- **완료 조건:** 정상 해석, 오류 후 재시도, 두 건 이상 저장 후 새로고침·다시 열기·개별 삭제를 자동 검사와 실제 화면에서 확인합니다.
- **자세한 명세:** `docs/specs/002-gemini-interpretation-history.md`

## 12. 3단계 목표: Google 로그인과 계정 결과 보관

- Supabase Auth의 Google 로그인으로 사용자를 식별합니다. 로그인 전에는 기존 사주 계산과 기본 성향, 이전 브라우저 기록 열람을 허용하되, 새 Gemini 자세한 해석과 저장은 로그인 후에만 허용합니다.
- 로그인 후 새 해석 결과는 사용자별 접근 규칙이 적용된 Supabase 데이터베이스에 저장합니다. 이전 `localStorage` 기록은 자동 이전하거나 삭제하지 않고 별도로 보여줍니다.
- 자세한 범위와 실패·검증 기준은 `docs/specs/003-google-login.md`, `docs/specs/004-interpretation-database.md`에 따릅니다.
- 현재 코드와 원격 데이터베이스 테이블·접근 정책은 작성됐지만 실제 Google 로그인 및 계정별 저장·조회·삭제 검증이 남아 있어 3단계는 완료 전입니다.

## 13. 4단계 목표: 사주 기반 로스트아크 직업 추천

- 로그인 사용자가 **자세히 해석하기**를 누르면 Gemini가 기존 성향·강점·주의점과 함께 현재 플레이 가능한 로스트아크 세부 직업 **한 개**와 쉬운 추천 이유를 제안합니다. 사주가 실제 적성이나 게임 성능을 증명한다는 뜻이 아닌 오락용 추천임을 알립니다.
- 추천 직업과 이유를 새 해석의 계정 기록에 함께 저장해 다시 열어도 같은 결과를 보여줍니다. 도입 전 기록은 변경하지 않고 추천 없음으로 표시합니다.
- 자세한 해석에 추천 직업이 있으면 기존에 생성한 SD 캐릭터 그림에서 그 직업의 모습도 함께 보여줍니다. 그림은 원본을 보존하고, 직업명으로 화면에서 연결합니다. 이미지나 경로를 데이터베이스에 새로 저장하지 않습니다.
- 모델 실패·잘못된 직업명/응답이면 가짜 결과를 만들거나 저장하지 않고 오류와 재시도를 보여줍니다. 데이터베이스 저장만 실패하면 화면의 결과는 보여주되 미저장 상태를 알립니다.
- 상세 범위와 완료 기준은 `docs/specs/005-lost-ark-class-recommendation.md`에 따릅니다. 로컬 코드와 Supabase 추천 열은 반영됐지만 실제 Google 로그인·Gemini 추천·계정 저장 흐름 검증이 남아 있어 완료 전입니다.

## 14. 5단계 목표: 오행 개수와 기본 뜻

- 사주 계산 직후 기존 결과에 목·화·토·금·수 각각의 개수와 쉬운 기본 뜻을 보여줍니다. 로그인이나 Gemini 호출 없이 현재 계산 결과를 사용합니다.
- 개수는 네 기둥의 대표 오행 8개를 단순 집계한 값이며, 오행의 강약·부족함이나 실제 성격을 확정하지 않는다는 안내를 함께 표시합니다. 이전 기록을 다시 열 때도 저장된 계산 결과로 표시합니다.
- 잘못된 입력이나 손상된 오행 값에서는 임의의 숫자·설명을 만들어내지 않습니다. 자세한 범위와 완료 기준은 `docs/specs/006-five-elements-overview.md`에 따르며, 화면과 자동 검증을 완료했습니다.

## 15. 6단계 목표: 잘 맞는 사람 유형 안내

- 로그인 사용자가 **자세히 해석하기**를 누르면 Gemini가 기존 해석·직업 추천과 함께 내 오행과 성향을 참고해 함께 지내기 편할 수 있는 사람의 오행·성향 **2~3가지 유형**과 이유를 쉬운 말로 설명합니다. 다른 사람의 생년월일을 입력받거나 실제 두 사람의 궁합을 계산하지 않습니다.
- 서버의 `lib/saju`가 계산한 결과만 Gemini에 전달합니다. 오행 8자의 단순 개수를 강약·결핍 판정으로 쓰지 않으며, 추천은 관계의 성공이나 실제 성격을 보장하지 않는 오락용 안내로 표시합니다.
- 유효한 새 결과는 기존 해석과 함께 계정 기록에 저장합니다. 이전 기록은 자동으로 채우지 않고 유형 없음으로 표시합니다. 잘못된 모델 응답은 저장하지 않고 오류·재시도를 안내하며, 저장만 실패하면 화면 결과와 미저장 상태를 알립니다.
- 상세 범위와 완료 기준은 `docs/specs/008-compatible-person-types.md`에 따릅니다. 로컬 구현·자동 검증과 DB 열 반영은 마쳤으며, 실제 로그인 후 Gemini 생성·계정 기록 재열기 화면 검증이 남아 있습니다.

## 16. 7단계 목표: 내 오행과 상생·상극 그림

- 계산 결과의 일간 오행을 **내 오행 유형**으로 표시하고, 목·화·토·금·수의 전통적인 상생·상극 흐름을 화살표 그림으로 보여줍니다. 상생은 목→화→토→금→수→목, 상극은 목→토→수→화→금→목입니다.
- 그림의 내 오행은 텍스트와 테두리로 강조하며, 그림을 읽기 어려워도 나를 돕는·내가 돕는·나를 견제하는·내가 견제하는 오행을 텍스트로 확인할 수 있게 합니다.
- 그림 자체는 계산된 일간으로 그리며 Gemini에게 오행 계산이나 그림 생성을 맡기지 않습니다. 현재 화면에서는 유효한 **자세한 해석 결과가 표시될 때** 그림을 함께 보여주고, 저장된 해석을 다시 열 때도 같은 위치에 표시합니다. 실제 사람 사이의 궁합·성격·관계 결과를 확정하는 기능은 아닙니다. 유효하지 않은 일간 값은 추측해 표시하지 않습니다.
- 상세 범위와 검증 기준은 `docs/specs/009-five-elements-relations.md`에 따릅니다.

## 17. 8단계 목표: 오행 그림을 자세한 해석에 배치

- 사주 계산 직후에는 일간·기본 성향·오행 개수를 보여주되, 오행 상생·상극 그림은 표시하지 않습니다. Gemini 자세한 해석이 성공해 화면에 나타나면 그 해석 영역 안에서 그림을 보여줍니다.
- 계정 저장 실패라도 유효한 해석이 화면에 표시되면 그림을 보여줍니다. 기존 계정·브라우저 기록을 다시 열 때 저장된 해석이 있으면 그림을 보여줍니다. 해석 요청 실패·새 입력·해석 재요청 중에는 이전 그림이 남지 않습니다.
- 그림은 기존 `chart.dayMaster.element`를 사용하는 결정적 SVG이며 추가 Gemini 호출이나 저장 항목은 없습니다. 상세 기준은 `docs/specs/010-five-elements-in-detailed-reading.md`에 따릅니다.
