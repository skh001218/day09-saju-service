# 015: 자세한 해석의 일일 금전운·건강운·직장운

## 목적과 확정한 범위

로그인 사용자가 **자세히 해석하기**를 완료했을 때, 그날의 금전운·건강운·직장운을 자세한 해석에서 함께 볼 수 있게 합니다. 사용자는 세 문구를 **매일 Gemini가 생성**하고 **계정 DB에 저장**하며 **자세한 해석에서만 표시**하기로 결정했습니다. 기존 기본 결과의 결정적 **오늘의 운세**와 별개의 기능입니다.

## 사용자 흐름

1. 사용자가 로그인하고 유효한 사주에서 **자세히 해석하기**를 눌러 해석이 계정 기록에 저장되면, 자세한 해석 영역에 한국 날짜와 금전운·건강운·직장운을 표시합니다. 기존 Gemini 해석 응답과 주제별 일일 운세 요청은 독립적으로 처리해, 주제 운세 오류가 성향·강점·주의점 등의 해석을 숨기지 않습니다.
2. 같은 계정·양력 생년월일·출생시간·한국 날짜에 저장된 주제 운세가 있으면 Gemini를 다시 호출하지 않고 저장된 세 문구를 보여줍니다. 같은 입력으로 자세한 해석 기록이 여러 건이어도 그날의 주제 운세는 한 건입니다.
3. 사용자가 저장된 **계정** 자세한 해석을 다시 열거나 새로고침·재로그인하면 현재 한국 날짜의 주제 운세를 조회합니다. 과거 해석 기록에 그 당시의 주제 운세를 고정해서 보여주거나 이전 날짜 기록을 자동 생성하지 않습니다. 이전 `localStorage` 기록만 있는 경우에는 계정 해석 기록으로 자동 이전하지 않습니다.
4. 한국 시간 자정에 날짜를 갱신하고, 화면을 계속 열어 두거나 탭을 다시 활성화했을 때 새 날짜의 결과를 요청합니다. 새 날짜의 요청이 실패하면 전날 문구를 오늘의 문구로 표시하지 않습니다. 다른 사주·계정·날짜의 늦은 응답이 현재 화면을 덮어쓰지 않습니다.
5. 세 문구 옆에 사주를 바탕으로 한 오락용 안내이며 재정·건강·직업 결정을 대신하지 않는다는 안내를 표시합니다. 생성 중, 저장됨, 생성 실패, 저장 실패, 로그인 만료 상태와 재시도 동작을 구분합니다.

## 생성 기준과 Gemini 응답

- 날짜는 서버가 정한 `Asia/Seoul` 양력 날짜입니다. 하루의 경계는 한국 시간 00:00입니다. 클라이언트가 보낸 날짜나 문구를 저장 기준으로 신뢰하지 않습니다.
- 서버는 기존 `lib/saju`로 출생 사주를 재계산하고, 012 Spec과 같은 한국 날짜 **정오**의 일주를 계산합니다. 출생 사주의 네 기둥·일간·대표 오행과 오늘 일주의 천간·지지 및 날짜를 Gemini에 전달합니다. 생년월일·출생시간 원문, 계정 ID, 인증 토큰은 전달하지 않습니다. Gemini에게 사주·일주 계산을 맡기지 않습니다.
- Gemini는 `money`, `health`, `work` 세 문자열을 **각각 한국어 1~2문장, 공백 제거 후 10~300자**로 반환합니다. 금전운은 지출 점검 등 가벼운 생활 제안, 건강운은 휴식·생활 습관에 대한 일반적 제안, 직장운은 업무·협업에 대한 일반적 제안을 다룹니다. 직장이 없는 사람도 읽을 수 있게 직업 상태를 추정하거나 특정 직장을 전제하지 않습니다.
- 프롬프트는 수익률·투자 종목·대출 결정, 질병명·진단·치료·약 복용, 합격·승진·해고 같은 결과 예측, 길흉 점수와 불안을 주는 단정을 금지합니다. 서버는 응답의 필드·형식·길이·빈 값과 명백한 금지 표현을 검사합니다. 자동 검사로 판정하기 어려운 문구의 적절성은 실제 화면 검증에 포함합니다. 유효하지 않은 응답은 일부 항목만 채우거나 가짜 문구로 대체하지 않습니다.
- 생성 모델과 프롬프트 버전을 서버에서 관리하고 DB에 `fortune_version`과 모델명을 함께 저장합니다. 규칙이 바뀌어도 이미 저장된 같은 날짜의 유효한 문구는 덮어쓰지 않습니다. Gemini 호출은 서버에서만 수행하고 `GEMINI_API_KEY`는 환경변수로만 읽습니다.

## DB와 API

- 새 SQL migration으로 `public.saju_daily_topic_fortunes`를 만듭니다. 기존 `saju_daily_fortunes`의 오늘의 흐름·행동·주의점, `saju_interpretations`의 날짜와 무관한 자세한 해석은 수정하지 않습니다.
- 필수 열: `id` UUID 기본키, `user_id` UUID(`auth.users` 참조), `birth_date` date, `birth_time` time, `fortune_date` date, `today_pillar` 2자 간지, `money`·`health`·`work` 비어 있지 않은 text, `fortune_version` 양의 정수, `model` text, `created_at` timestamptz. 세 문구에는 10~300자 제약을 둡니다. `(user_id, birth_date, birth_time, fortune_date)`를 고유 키로 두고 동시 요청에도 한 건만 남깁니다.
- RLS를 활성화하고 인증 사용자에게 자신의 행에 대한 `SELECT`, `INSERT`만 허용합니다. 익명 접근, 수정, 삭제는 이번 범위에서 제공하지 않습니다. `user_id`는 검증된 서버 세션에서 가져옵니다. 출생정보는 기존 계정 해석과 같은 범위의 개인정보이므로 로그·오류 응답에 싣지 않습니다.
- 인증이 필요한 별도 주제 운세 API는 출생 날짜·시간만 입력받습니다. 과도한 본문과 잘못된 입력을 거부하고, 서버가 사주·현재 한국 날짜를 재계산합니다. 해당 사용자·출생정보의 **저장된 계정 자세한 해석 기록**이 있는지 확인한 뒤 주제 운세를 조회·생성합니다. 기록이 없으면 생성하지 않습니다. 응답은 `Cache-Control: no-store`를 사용합니다.
- 먼저 같은 키의 저장 행을 조회하고 형식을 검사합니다. 없으면 Gemini를 호출해 검증 후 삽입합니다. 고유 키 충돌 시 기존 행을 다시 읽어 반환합니다. 손상된 행은 성공 처리하거나 새 문구로 덮어쓰지 않습니다. Gemini 실패에는 새 행을 쓰지 않습니다.
- DB 삽입만 실패한 경우에는 검증된 세 문구를 현재 화면에 **미저장**으로 표시하고 재시도할 수 있게 합니다. 재요청 시 저장된 행이 생겼다면 그 행을 우선 사용합니다. 여전히 저장되지 않은 경우 재생성될 수 있으므로 새로고침 이후 동일 문구는 보장하지 않습니다. 저장된 결과에 대해서만 같은 날짜의 동일 문구를 보장합니다.

## 실패와 경계

- 비로그인·만료 세션, 유효하지 않은 출생 입력, 해당 계정의 자세한 해석 기록 없음, Gemini 키 누락·호출 실패·시간 초과·응답 불량, DB 조회·삽입 실패를 구분해 안내합니다. 재시도는 주제 운세만 다시 요청하며 기존 자세한 해석이나 기본 오늘의 운세를 새로 생성하지 않습니다.
- 기존 자세한 해석의 계정 저장이 실패해 해석만 화면에 보이는 경우에는 계정 기록이 확인될 때까지 주제 운세를 요청하지 않고 저장 실패 안내를 유지합니다. 사용자가 다시 시도해 해석이 저장되면 주제 운세를 요청할 수 있습니다.
- 같은 날짜의 여러 해석 기록, 동시 탭·중복 클릭, 계정 전환, 새 사주 입력, 자정 경계, 늦은 요청 응답에서 세 문구가 다른 결과에 붙지 않아야 합니다.

## 범위에서 제외

- 기본 사주 결과나 비로그인 화면의 주제별 운세, 기존 결정적 오늘의 운세 대체
- 지난 날짜의 주제 운세 목록·수정·삭제·공유, 알림과 Cron 예약 생성
- Gemini를 이용한 사주 계산, 실제 재정·의료·고용 판단이나 결과 보장

## 완료 조건과 검증

1. 자세한 해석이 저장된 로그인 사용자는 세 주제와 한국 날짜를 보고, 같은 계정·출생정보·날짜의 재열기·새로고침·재로그인에서는 저장된 문구를 재사용하며 Gemini 추가 호출과 DB 중복 행이 없습니다. 다른 계정·출생정보·날짜는 분리됩니다.
2. 한국 시간 자정 전후, 열린 탭, 탭 재활성화에서 날짜가 바뀌며 전날 문구가 오늘 것으로 남지 않습니다. 중복·늦은 응답이 현재 사주 화면을 덮지 않습니다.
3. 비로그인, 입력 오류, 해석 기록 없음, Gemini 실패·불량 응답에는 새 DB 행이 없고 기존 사주·자세한 해석이 유지됩니다. DB 저장 실패는 미저장 표시와 재시도를 제공하며 저장 성공으로 오인되지 않습니다.
4. RLS와 API에서 다른 사용자 행 접근, 클라이언트의 사용자 ID·날짜·문구 조작, 인증 없는 호출을 차단합니다. 금전·건강·직장 문구와 안내가 모바일에서도 읽히고 위험한 단정 표현이 없는지 실제 화면에서 확인합니다.
5. 관련 자동 테스트, 타입 검사, 빌드, 실제 로그인·Gemini·DB 저장·재조회·오류·재시도를 확인합니다. 기존 기본 오늘의 운세, 자세한 해석, 계정 기록 재열기도 다시 확인하고 결과를 이 문서에 기록한 후에만 `docs/status.md`를 완료로 표시합니다. DB migration이 실제 대상 환경에 적용되지 않았다면 완료로 표시하지 않습니다.

## 검증 결과

- 2026-09-28: 요구사항을 문서로 정의했습니다. 이후 주제 운세 Gemini 생성·형식 검사, 계정 기록 확인과 날짜별 조회·저장 API, RLS migration, 자세한 해석의 주제 운세 화면을 구현했습니다.
- 구현을 맡지 않은 테스트 담당이 검증·Gemini·API·migration·화면 연결 테스트 13개를 추가했습니다. 주 에이전트의 `npm run check`에서 타입 검사와 전체 테스트 116개가 통과했고, `npm run build`도 통과했습니다. `git diff --check`에서 서식 오류가 없었습니다.
- 로컬 브라우저에서 공개 화면을 열고 `2000-01-01 12:00` 사주 계산, 기본 성향·오행·기존 오늘의 운세 표시를 확인했습니다. 이 환경에는 로그인·Gemini·Supabase 설정이 없어 실제 계정의 생성·저장·재조회·자정 갱신·오류 재시도 화면은 검증하지 못했습니다. migration도 실제 DB에 적용하지 않았으므로 완료 체크는 보류합니다.
