# 016: 생년월일별 주제 운세 구분

## 목적

서로 다른 출생정보로 보는 당일 금전운·건강운·직장운이 동일한 범용 문구로 나오지 않게 한다. 사용자가 요청한 대로 오늘 이미 저장된 중복 문구도 새로 생성해 교체한다.

## 동작

- 기존 사주 계산과 한국 날짜 계산을 유지한다. Gemini에는 생년월일·출생시간 원문 대신 계산된 네 기둥, 오행과 오늘 일주를 보낸다.
- 프롬프트에 각 기둥의 한글 표기와 주제별 사주 연결을 명시하고, 출생 사주와 무관한 범용 문구만 작성하지 않도록 요청한다. 같은 계정의 다른 출생정보에 이미 생성된 주제 문구 최대 5건을 피할 사례로 전달한다. 원본 생년월일·출생시간·계정 ID는 전달하지 않는다.
- 같은 계정·한국 날짜에 저장된 다른 출생정보의 세 항목을 조회한다. 현재 입력의 항목이 다른 출생정보의 같은 항목과 공백을 정규화한 뒤 동일하면 중복으로 본다.
- 기존 1 버전 행은 표현만 조금 다른 같은 제안일 수 있으므로 오늘 조회할 때 새 문구 세 개를 생성해 갱신한다. 2 버전부터는 세 항목 중 하나라도 문자상 중복이면 재생성하고, 중복이 없으면 저장 문구를 그대로 재사용한다.
- 새 문구가 중복이면 최대 세 번 생성한다. 끝내 구분되지 않으면 성공으로 저장하지 않고 재시도 가능한 오류를 반환한다. Gemini 실패나 형식 불량일 때 기존 행을 유지한다.
- 갱신은 본인 행의 문구·버전·모델에만 허용한다. 출생정보, 날짜, 소유자와 생성 시각은 변경하지 않는다. 갱신 실패 시 중복된 옛 문구를 새 결과로 표시하지 않는다.
- 동시 요청으로 같은 키의 삽입이 충돌하면 저장 행을 다시 확인한다. 다른 출생정보와 문구 중복이 확인되면 같은 규칙으로 재생성한다.

## 검증

- 서로 다른 출생정보에 같은 항목 문구를 생성하면 재시도하고, 중복이 없는 문구만 저장하는지 확인한다.
- 이미 저장된 중복 행은 갱신되고, 중복이 없는 행은 Gemini 호출 없이 재사용하는지 확인한다.
- 조회·생성·갱신 실패 및 다른 계정 행의 격리를 확인한다.
- 타입 검사, 관련 테스트, 전체 테스트, 빌드와 기존 기본 운세/해석 흐름을 재확인한다. 실제 DB migration 및 실 서버 동작 확인 결과를 기록한 뒤 완료로 표시한다.

## 검증 결과

- 2026-09-28: 실 DB에서 오늘 서로 다른 출생정보 2건의 세 항목은 각각 문자열이 달랐지만, 금전운은 두 문구 모두 불필요한 지출 점검과 예산 정리, 건강운은 차·휴식·스트레칭, 직장운은 소통·협업을 권했습니다. 문자열 중복만으로는 이 현상을 잡을 수 없어 기존 1 버전 행을 조회 시 갱신하고, 다른 사주에 쓴 제안을 새 프롬프트의 피할 사례로 전달하도록 했습니다.
- 구현을 맡지 않은 테스트 담당이 관련 API·프롬프트·권한 테스트를 보강했습니다. `npm run check`에서 타입 검사와 전체 테스트 127개가 통과했고, 주 에이전트의 `npm run build`도 통과했습니다.
- 운영 Supabase에 갱신 권한과 본인 행 RLS 정책을 적용했습니다. 읽기 전용 SQL로 UPDATE 정책 1개와 허용된 UPDATE 열 5개를 확인했습니다.
- 변경된 API가 운영 환경에 아직 배포되지 않아 실제 Gemini 생성·저장 행 교체·화면 재조회는 검증 전입니다. 완료 체크는 보류합니다.
