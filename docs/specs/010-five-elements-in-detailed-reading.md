# 010: 자세한 해석에서 오행 그림 표시

## 목적과 범위

009에서 사주 계산 직후 보여주던 오행 상생·상극 그림을 사용자가 **Gemini 자세한 해석을 볼 때** 함께 볼 수 있게 배치합니다. 사용자가 말한 오행 이미지는 기존 다섯 원과 상생·상극 화살표 SVG를 뜻합니다. 009의 오행 관계·일간 강조·접근성·주의 문구는 유지하며 이 Spec은 표시 시점과 위치만 변경합니다.

## 사용자 흐름

1. **내 사주 알아보기**만 완료하면 기존 일간·기본 성향·네 기둥·오행 개수와 기본 뜻을 표시합니다. 오행 상생·상극 그림은 숨깁니다.
2. 로그인 사용자가 **자세히 해석하기**를 누르고 유효한 Gemini 결과가 화면에 표시되면, 같은 `자세한 사주 해석` 영역 안에 그림을 함께 표시합니다. 그림은 기존 `chart.dayMaster.element`로 그리며 Gemini에게 오행 계산이나 이미지 생성을 맡기지 않습니다.
3. 유효한 해석을 받았지만 계정 저장만 실패한 경우, 기존 정책대로 해석과 미저장 안내를 표시하며 그림도 함께 표시합니다.
4. 이전 계정 기록 또는 브라우저 기록을 다시 열었을 때 저장된 해석이 있으면 같은 그림을 표시합니다. 해당 기록에 해석이 없으면 그림을 만들지 않습니다.
5. 새 입력, 기록 전환 중, 해석 재요청 중, 해석 실패·잘못된 응답 시 이전 그림이 남지 않습니다. 계산 결과와 오행 개수는 기존 오류·재시도 정책대로 유지합니다.

## 데이터와 실패 조건

- 추가 Gemini 호출, 응답 필드, 프롬프트, 저장 열, API는 없습니다. 새 그림은 기존 검증된 일간 오행의 읽기 전용 표현입니다.
- 해석이 유효해도 일간 오행이 손상되었으면 009의 안전 안내를 표시하고 개인화된 관계는 추측하지 않습니다.
- 로그인하지 않은 사용자가 계산만 한 경우 그림이 보이지 않습니다. 과거 브라우저 기록에 유효한 해석이 있으면 로그인하지 않아도 그 기록의 그림은 볼 수 있습니다.

## 범위에서 제외

- 오행별 생성 이미지, Gemini 이미지 생성, 새로운 궁합 계산
- 기존 009의 상생·상극 계산 방식이나 006의 오행 개수 표시 변경

## 완료 조건

1. 계산 직후에는 그림이 없고 오행 개수는 계속 표시됩니다. 자세한 해석이 표시되면 그림이 같은 영역 안에 나타납니다.
2. 해석 실패·재요청·새 입력에는 이전 그림이 남지 않고, 유효 해석의 저장만 실패하면 그림은 표시됩니다.
3. 계정·브라우저 저장 기록 재열기에서 기존 해석과 그림이 함께 나타납니다.
4. 관련 자동 테스트, 타입 검사, 빌드, 가능한 실제 화면 검증을 수행하고 결과를 아래에 기록합니다.

## 검증 결과

- 2026-09-23: 비구현 테스트 담당이 계산 결과와 자세한 해석 영역의 표시 경계, 유효 해석의 성공·DB 저장 실패·계정/브라우저 기록 재열기, 새 입력·재계산·로딩·오류 초기화를 확인하는 회귀 테스트 3개를 추가했습니다.
- 주 에이전트의 `npm run check`에서 TypeScript 검사와 전체 테스트 77개가 통과했고, `npm run build`도 통과했습니다. 기존 오행 관계와 Gemini/API 테스트도 함께 통과했습니다.
- 로컬 브라우저에서 `2000-01-01 12:00` 계산 후 오행 개수는 보이고 그림은 없는 것을 확인했습니다. 로그인하지 않은 상태에서 해석 버튼을 눌러 로그인 안내가 나와도 그림은 나타나지 않았습니다.
- 로컬 개발 환경에는 Google 로그인 설정이 없어 Gemini 성공·계정 저장 실패·계정 기록 재열기의 실제 화면은 확인하지 못했습니다. 해당 경로의 해석 상태와 그림의 조건부 렌더링은 자동 테스트로 확인했습니다.
