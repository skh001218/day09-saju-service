# 013: Vercel Cron을 이용한 해석 기록 회원의 일일 운세 저장

## 목적과 범위

자세한 해석을 계정에 저장한 회원에게 매일 운세를 미리 저장합니다. 2026-09-28 사용자 결정에 따라 자세한 해석 기록이 없는 회원은 예약 생성 대상에서 제외합니다. 기본 사주 계산만으로 출생정보를 서버 프로필에 저장하지 않습니다.

## 데이터와 실행 규칙

- `public.saju_interpretations`의 회원별 가장 최근 기록을 사용합니다. 최신 순서는 `created_at` 내림차순, 동률이면 `id` 내림차순입니다. 기록을 모두 삭제한 회원은 다음 예약 실행부터 제외합니다.
- 기존 `public.saju_daily_fortunes`에 `(user_id, birth_date, birth_time, fortune_date)`별 한 건을 보관합니다. `fortune_version`을 포함하며, 같은 키의 기존 운세 문구는 덮어쓰지 않습니다. 회원의 해석 기록에서 출생정보가 바뀌면 새로운 출생정보의 운세가 별도 행으로 저장될 수 있습니다.
- Cron은 `user_id` 오름차순으로 최대 100개 기록을 조회하고, 조회 범위에서 회원별 최신 기록 한 개만 처리합니다. 다음 조회는 마지막 `user_id` 이후부터 시작합니다. 한 회원의 기록이 페이지 경계에 걸려도 그 회원을 중복 처리하지 않습니다.
- 사주와 운세는 `lib/saju`에서 계산합니다. Gemini는 예약 생성에 사용하지 않습니다.
- `vercel.json`의 `0 0 * * *`는 UTC 자정, 한국시간 매일 오전 9시입니다. Vercel Cron은 프로덕션 배포에만 적용됩니다.
- `/api/cron/daily-fortunes`는 `CRON_SECRET`과 Bearer 헤더가 일치할 때만 실행합니다. 누락된 설정, 조회·계산·저장 오류는 성공으로 처리하지 않습니다. 응답의 `saved`는 처리한 회원 수입니다.
- 일반 사용자는 계정의 오늘 운세를 기존 `/api/daily-fortune` 경로에서 별도로 저장하고 읽을 수 있습니다. 그 경로는 해석 기록 유무와 관계없이 유지합니다.

## 실패와 개인정보

- 해석 기록이 없는 회원은 예약 운세가 생성되지 않습니다. 로그인 후 기본 사주만 계산해도 예약 생성 대상이 되지 않는다고 화면에 안내합니다.
- 잘못된 출생정보, 인증 실패, 누락된 환경변수, DB 오류, 잘못된 예약 헤더에서는 저장을 중단하고 실패 응답을 돌려줍니다. 개인 입력값과 비밀키는 로그나 HTTP 응답에 싣지 않습니다.
- `CRON_SECRET`과 `SUPABASE_SECRET_KEY`는 서버 환경변수로만 관리합니다. 기존 publishable key와 구별합니다.

## 완료 조건

1. 최신 해석 기록이 있는 회원만 예약 운세 대상에 포함되고, 여러 해석 기록 중 최신 출생정보가 사용됩니다.
2. 한국시간 오전 9시 일정, 인증 실패 차단, 날짜별 중복 방지, 페이지 경계와 DB 오류 처리를 테스트합니다.
3. 이전 프로필 저장 요청과 관련 화면 문구를 제거하고 기존 계산·해석·계정 운세 저장 흐름을 다시 확인합니다.
4. 타입 검사, 관련 테스트, 배포 빌드를 통과하고 실제 Vercel Cron 호출에서 저장 성공을 확인합니다.

## 배포 설정

1. Supabase 프로젝트에 `supabase/migrations/20260928000200_create_saju_daily_fortunes.sql`이 적용되어 있는지 확인합니다. 이전 방식의 `saju_profiles`, `daily_fortunes`는 이 방식에 필요하지 않습니다.
2. Vercel 프로덕션 환경변수에 `CRON_SECRET`(최소 16자 임의 문자열), `SUPABASE_SECRET_KEY`(서버 전용 Supabase secret key), `NEXT_PUBLIC_SUPABASE_URL`을 설정합니다.
3. 프로덕션에 배포한 뒤 Cron Jobs에서 `/api/cron/daily-fortunes`의 실행 결과와 저장 행을 확인합니다. 오류가 나면 함수 로그와 DB 로그를 확인하고 인증 헤더로 수동 재실행할 수 있습니다.

## 검증 결과

- 2026-09-28 이전 구현은 `saju_profiles`와 `daily_fortunes`를 사용했으나, 실제 프로젝트에서 두 테이블이 PostgREST `PGRST205`로 조회되지 않아 Cron이 503으로 실패했습니다. 같은 프로젝트의 `saju_daily_fortunes`는 존재했습니다.
- 2026-09-28 사용자가 예약 대상 범위를 해석 기록이 있는 회원으로 변경했습니다. 이전 프로필 API와 사용하지 않는 migration을 제거하고, 최신 해석 기록을 조회해 기존 운세 테이블에 저장하도록 변경했습니다.
- 비구현 테스트 담당이 인증, 대상 제외, 최신 기록, 201명 페이지 처리와 경계 중복, DB 오류, 재실행을 다루는 Cron 테스트 9개를 작성·실행했고 모두 통과했습니다. 주 에이전트의 `npm run check`에서 전체 103개 테스트와 타입 검사가 통과했고 `npm run build`도 통과했습니다.
- 실제 Vercel 배포와 Cron 실행 결과는 아직 검증하지 않았으므로 `docs/status.md`는 미완료 상태로 유지합니다.
