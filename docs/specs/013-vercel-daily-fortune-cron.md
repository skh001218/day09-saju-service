# 013: Vercel Cron을 이용한 회원별 일일 운세 저장

## 목적과 범위

자세한 해석 기록이 없는 로그인 회원도 출생정보를 입력했다면 매일의 개인 운세를 서버에 저장할 수 있게 합니다. 로그인 상태에서 **내 사주 알아보기**를 실행한 입력을 해당 계정의 프로필에 보관하고, Vercel Cron이 매일 한국시간 오전 9시에 프로필이 있는 회원을 처리합니다. 한 번도 출생정보를 입력하지 않은 계정은 계산할 근거가 없어 건너뜁니다.

## 데이터와 실행 규칙

- `public.saju_profiles`: `user_id`별 양력 생년월일과 출생시간 한 건. 새 계산을 실행하면 최신 입력으로 갱신합니다. 기존 해석 기록만 있는 회원은 migration에서 가장 최근 기록의 입력으로 초기 프로필을 생성합니다.
- `public.daily_fortunes`: `(user_id, fortune_date)`별 한 건. 기존 `lib/saju`의 결정적 운세 필드와 생성 시각을 보관합니다. 운세 자체를 Gemini로 생성하지 않습니다.
- 프로필을 새로 저장하거나 바꾸면 현재 한국 날짜의 운세도 즉시 저장합니다. 오전 9시 예약 실행이 지난 후에 처음 입력해도 당일 운세가 남습니다.
- 사주 입력과 프로필 저장 API는 서버에서 로그인 세션 및 입력값을 검증합니다. 클라이언트의 사용자 ID나 계산된 사주는 신뢰하지 않습니다. 프로필과 운세는 본인만 읽을 수 있고, 쓰기는 검증된 서버 경로만 수행합니다. 예약 실행은 서버 전용 Supabase secret key로 처리합니다.
- `vercel.json`의 `0 0 * * *`는 UTC 자정, 한국시간 매일 오전 9시입니다. Vercel Cron은 프로덕션 배포에만 적용됩니다. Hobby 플랜에서는 지정한 9시부터 9시 59분 사이 실행될 수 있습니다.
- `/api/cron/daily-fortunes`는 설정된 `CRON_SECRET`과 Bearer 헤더가 일치할 때만 실행됩니다. 비밀값이 없으면 작업을 거부합니다. 중복 호출은 날짜·회원별 upsert로 안전하게 처리합니다. 배치 조회와 쓰기 오류는 성공으로 처리하지 않습니다.
- 기존 화면의 한국시간 자정 갱신은 유지합니다. 저장된 운세를 보여줄 때도 화면의 현재 날짜와 저장 행의 날짜가 같아야 합니다.

## 화면 표시

- 로그인 회원에게는 본인 계정의 **오늘 저장된 운세 한 건**을 `오늘의 운세` 영역에 표시합니다. 기준은 `Asia/Seoul`의 현재 날짜이며, 다른 회원의 운세와 지난 날짜의 저장 운세는 이 화면에서 조회하거나 표시하지 않습니다.
- 저장된 운세의 **오늘의 흐름**, **해볼 만한 행동**, **주의할 점**과 기준 날짜를 보여주고, `계정에 저장된 오늘의 운세`임을 표시합니다. 기존 오락용 안내도 유지합니다. 로그인 직후 아직 사주를 다시 계산하지 않았더라도 저장된 오늘 운세가 있으면 볼 수 있습니다.
- 저장된 행이 없거나 조회에 실패했지만 현재 화면에 유효한 사주가 있으면 기존 `lib/saju` 규칙으로 오늘 운세를 계산해 표시합니다. 행이 없는 것이 확인되면 `화면에서 계산한 운세 · 아직 계정에 저장되지 않음`, 조회 실패라면 `화면에서 계산한 운세 · 계정 저장 여부 미확인`처럼 상태를 구분하고 다시 조회할 수 있게 합니다. 유효한 사주도 없다면 운세를 꾸며내지 않고 출생정보 입력 또는 재시도 안내를 보여줍니다.
- 현재 연 사주 결과가 계정 프로필의 출생정보와 다르면 그 결과에 계정의 저장 운세를 끼워 넣지 않습니다. 현재 결과의 운세는 해당 사주로 계산하고, 계정에 저장된 오늘 운세와 출처를 분리해 표시합니다. 같은 운세를 화면에 중복해서 배치하지 않습니다.
- 한국시간 자정이 지나면 전날 저장 행을 즉시 숨기고 새 날짜를 조회합니다. 로그인·로그아웃, 계정 전환, 새 계산, 기록 재열기, 탭 재활성화에서도 표시 대상과 저장 여부를 다시 확인합니다. 이전 계정의 운세나 전날 운세를 새 계정·새 날짜의 결과로 남겨 두지 않습니다.
- 조회 API는 서버에서 세션을 검증하고 현재 한국 날짜의 본인 행만 반환합니다. 응답에 `Cache-Control: no-store`를 적용하며 비밀키·타인 데이터·불필요한 출생정보를 넣지 않습니다. 운세 조회가 화면의 기본 사주 계산이나 Gemini 해석을 막지 않습니다.

## 실패와 개인정보

- 로그인하지 않은 계산은 기존처럼 화면에서만 동작하며 계정 프로필을 만들지 않습니다. 로그인 회원의 프로필 또는 당일 운세 저장 실패는 화면에 알리고 재계산으로 재시도할 수 있게 합니다.
- 비로그인 사용자의 `오늘의 운세`는 기존처럼 현재 사주로만 계산합니다. 로그인 회원의 운세 조회가 실패해도 기존 계산 결과를 유지하고, 저장 성공이나 저장된 문구를 추측해 표시하지 않습니다.
- 잘못된 출생정보, 인증 실패, 누락된 환경변수, DB 오류, 잘못된 예약 헤더에서는 저장을 중단하고 실패 응답을 돌려줍니다. 개인 입력값과 비밀키는 로그나 HTTP 응답에 싣지 않습니다.
- `CRON_SECRET`과 `SUPABASE_SECRET_KEY`는 서버 환경변수로만 관리합니다. 기존 publishable key와 구별합니다.

## 완료 조건

1. 로그인 회원의 기본 사주 계산으로 프로필이 저장되며, 자세한 해석 기록이 없어도 예약 운세 대상에 포함됩니다.
2. 한국시간 오전 9시 일정, 인증 실패 차단, 날짜별 중복 방지, 여러 페이지의 프로필 처리, DB 오류 처리를 테스트합니다.
3. RLS 정책과 프로필 입력 검증, 기존 사주 계산·운세·해석 흐름을 검사합니다.
4. 타입 검사, 관련 테스트, 배포 빌드를 통과하고, 실제 Vercel 환경변수와 DB migration 적용 후 예약 실행을 확인합니다.
5. 로그인 직후 저장된 오늘 운세가 보이고, 현재 사주 결과와 계정 운세가 다를 때 출처가 섞이지 않습니다. 저장 행 없음·조회 실패에서는 유효한 현재 사주만 계산 운세로 대체하고 저장 여부를 구분합니다. 자정·로그아웃·계정 전환 뒤 이전 사용자 또는 전날의 운세가 남지 않는지 자동 테스트와 실제 화면에서 확인합니다.

## 배포 설정

1. Supabase에서 `supabase/migrations/20260928000100_create_daily_fortunes.sql`을 적용합니다. 기존 해석 기록이 있는 계정은 최신 입력으로 프로필을 초기화합니다.
2. Vercel 프로덕션 환경변수에 `CRON_SECRET`(최소 16자 임의 문자열)과 `SUPABASE_SECRET_KEY`(서버 전용 Supabase secret key)를 등록합니다. 기존 `NEXT_PUBLIC_SUPABASE_URL`도 필요합니다. 두 비밀값에는 `NEXT_PUBLIC_` 접두어를 붙이지 않습니다.
3. 프로덕션에 배포한 뒤 Cron Jobs에서 `/api/cron/daily-fortunes`의 실행 결과를 확인합니다. Vercel은 실패한 Cron 요청을 자동 재시도하지 않으므로, 오류가 나면 설정·DB 로그를 확인하고 인증 헤더로 수동 재실행할 수 있습니다.

공식 문서: [Vercel Cron](https://vercel.com/docs/cron-jobs/manage-cron-jobs), [Supabase Secret Key](https://supabase.com/docs/guides/getting-started/api-keys).
