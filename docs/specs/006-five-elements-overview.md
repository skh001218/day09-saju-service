# 006: 사주 결과의 오행 개수와 기본 뜻 표시

## 목적과 확정한 범위

사주를 처음 접하는 사용자가 결과에 나온 목·화·토·금·수의 개수를 보고, 각 오행이 전통적으로 어떤 이미지로 설명되는지 쉬운 말로 이해하게 합니다. 사용자는 **계산된 다섯 오행의 개수와 기본 뜻을 결과 화면에 바로 표시**하는 방식을 선택했습니다. Gemini 해석은 이 기능에 사용하지 않습니다.

## 계산 근거와 주의 문구

- 기존 `SajuChart.elements`를 그대로 사용합니다. `lib/saju/chart.ts`는 네 기둥의 천간 4자와 지지 4자의 **대표 오행을 각각 한 번씩**, 총 8개를 셉니다. 같은 사주를 새 방식으로 다시 계산하거나 별도의 점수·가중치를 만들지 않습니다.
- 다섯 값은 0 이상의 정수이고 합계는 8이어야 합니다. 화면에서는 `목 → 화 → 토 → 금 → 수` 순서로 보여줍니다. 0개인 오행도 빠뜨리지 않고 `0개`로 표시합니다.
- 화면에는 “이 숫자는 사주 글자 8개의 대표 오행을 단순히 센 값입니다. 계절의 영향이나 숨은 오행(지장간)은 반영하지 않아, 오행의 강약·부족함이나 실제 성격을 단정할 수 없습니다.”라는 취지의 안내를 함께 표시합니다. `0개`를 ‘결핍’, 가장 큰 값을 ‘좋음/나쁨’, 다섯 개가 비슷해야 ‘건강함’으로 해석하지 않습니다.
- 사용자가 이미 보는 **일간 오행**과 이 표의 개수는 다른 정보입니다. 일간은 태어난 날의 천간 한 글자에 해당하며, 개수는 네 기둥의 대표 오행 여덟 글자를 센 값이라고 짧게 구분해 설명합니다.

## 화면과 문구

1. 사용자가 양력 생년월일과 출생시간으로 **내 사주 알아보기**를 누르면 기존 네 기둥·일간·기본 성향 아래에 **오행 살펴보기** 영역을 표시합니다. 이 영역은 계산 결과이므로 로그인하지 않아도 보입니다.
2. 각 오행마다 **이름, 개수(`n개`), 기본 뜻 한 문장**을 보입니다. 작은 화면에서도 글자와 숫자를 읽을 수 있게 하고, 색상만으로 오행을 구분하지 않습니다. 막대나 아이콘을 추가하더라도 이름·숫자 텍스트는 항상 남깁니다.
3. 기본 뜻은 다음의 고정 문구를 사용합니다. 이는 자연 이미지를 빌린 설명이지 사용자의 성격을 판정하는 문장이 아닙니다.

| 오행 | 표시할 기본 뜻 |
|---|---|
| 목 | 자라나고 뻗어 가는 나무의 이미지예요. |
| 화 | 밝히고 퍼지는 불의 이미지예요. |
| 토 | 받치고 이어 주는 땅의 이미지예요. |
| 금 | 단단하게 다듬고 정리하는 쇠의 이미지예요. |
| 수 | 흐르고 스며드는 물의 이미지예요. |

4. 기존 계정 기록이나 과거 브라우저 기록을 다시 열었을 때도 저장된 `chart.elements`로 같은 영역을 보여줍니다. 이 기능을 위해 과거 기록을 변경하거나 새 API/Gemini 요청을 하지 않습니다.
5. 새 입력을 시작해 이전 계산 결과를 지우면 오행 영역도 함께 지웁니다. 입력 오류에는 개수나 뜻을 임의로 표시하지 않고 기존 입력 안내를 유지합니다.

## 데이터와 안전

- 이 기능은 읽기 전용 표시입니다. Gemini 프롬프트·응답 형식, 로그인 정책, `localStorage`/Supabase 저장 구조, 기존 해석 기록을 바꾸지 않습니다.
- 화면에 표시하기 전 다섯 값이 모두 유효한 정수이고 합계가 8인지 확인합니다. 손상된 과거 기록처럼 값이 없거나 잘못된 경우에는 숫자를 추측해 채우지 않고 오행 영역만 안전하게 숨기거나 “오행 개수를 표시할 수 없습니다”라고 안내합니다. 기존의 정상적인 사주·해석 화면은 계속 열려야 합니다.
- 별도 생년월일·출생시간 수집이나 외부 전송은 추가하지 않습니다. 005 직업 추천 구현과는 독립적이며, 그 기능의 성공·실패가 오행 표시를 막지 않습니다.

## 이번 범위에서 제외

- 오행 강약·용신·희신·부족한 오행의 판정, 계절/지장간 가중치, 맞춤형 보완 조언
- Gemini의 오행 분포 해석 문단, 오행별 건강·재물·직업 예측
- 새 계산 엔진, 데이터베이스 열, 외부 API, 로그인 필수 조건

## 완료 조건과 검증 사례

1. 정상 계산에서 다섯 오행이 정해진 순서로 모두 나타나고, 각 개수의 합은 8이며 기본 뜻 문구가 정확히 표시됩니다. 0개도 생략하지 않습니다.
2. 비로그인 상태에서도 결과가 보이고, Gemini/계정 API를 새로 호출하지 않습니다.
3. 저장된 계정 기록과 예전 브라우저 기록을 다시 열면 그 기록의 `chart.elements`에 맞는 오행 영역이 표시되고 기존 데이터는 변하지 않습니다.
4. 잘못된 입력 또는 손상된 과거 오행 데이터에서는 잘못된 숫자·가짜 해석을 보여주지 않고 화면이 멈추지 않습니다.
5. 자동 테스트·타입 검사와 실제 화면에서 정상 입력, 0개 사례, 저장 기록 재열기, 오류 상황을 확인한 뒤에만 `docs/status.md`를 완료로 바꿉니다.

## 현재 상태

오행 표시 컴포넌트와 숫자 검증을 구현했습니다. 기존 계산·저장 구조와 Gemini 호출은 변경하지 않았습니다.
