# 002: Gemini 사주 해석과 결과 보관

## 목적

사주를 처음 접하는 사람이 네 기둥과 기본 성향 한 문장을 본 뒤, 성향·강점·주의점을 쉬운 말로 더 자세히 읽고 나중에 같은 브라우저에서 다시 볼 수 있게 합니다.

## 사용자가 결정한 범위

- Gemini 해석은 사주 계산 직후 자동 실행하지 않습니다. 사용자가 **자세히 해석하기**를 누르면 시작합니다.
- 해석은 **성향·강점·주의점** 세 부분으로 구성합니다.
- 생년월일, 출생시간, 계산 결과, Gemini 해석을 브라우저의 `localStorage`에 함께 저장합니다.
- 여러 결과를 쌓아 목록에서 다시 열 수 있게 합니다.

## 화면 흐름

1. 사용자가 기존 방식으로 양력 생년월일과 출생시간을 입력하고 **내 사주 알아보기**를 누릅니다.
2. 기존 사주 네 기둥과 기본 성향 한 문장을 즉시 보여줍니다.
3. 사용자가 **자세히 해석하기**를 누르면 진행 중 표시를 보여주고 중복 요청을 막습니다.
4. 해석에 성공하면 성향·강점·주의점을 각각 짧은 한국어 문단으로 보여주고, 해당 입력·사주·해석을 `localStorage`의 새 기록으로 저장합니다.
5. **저장된 결과** 목록에서 기록을 고르면 당시 입력·사주·해석을 다시 보여줍니다. 각 기록은 개별 삭제할 수 있습니다.
6. 사용자가 입력값을 수정하거나 새 계산을 시작하면 현재 표시된 해석이 새 입력의 결과로 오인되지 않도록 이전 해석 표시를 지웁니다.

## Gemini 입력과 출력

- 사주 계산은 기존 `lib/saju`가 담당합니다. 서버는 생년월일·출생시간을 검증하고 사주를 다시 계산하며, 브라우저가 보낸 사주 계산값을 그대로 신뢰하지 않습니다.
- Gemini에는 계산된 네 기둥, 일간, 오행 정보와 초보자용 해석 지침만 전달합니다. 원래 생년월일·출생시간은 Gemini에 전달하지 않습니다.
- Gemini에는 한국어로, 어려운 용어를 풀어서, 단정적 예언이나 불안을 주는 표현 없이 작성하도록 요청합니다. 해석은 참고용이며 실제 성격이나 미래를 확정하지 않는다는 안내를 화면에 표시합니다.
- Gemini 응답은 `성향`, `강점`, `주의점`의 세 문자열을 가진 구조화된 데이터로 받습니다. 서버는 세 항목의 존재와 문자열 길이·빈 값 여부를 검사한 뒤 화면에 전달합니다. 잘못된 형식은 성공으로 처리하지 않습니다.
- 각 항목은 화면에서 읽기 쉬운 짧은 문단(1~2문장)을 목표로 합니다. 현재 모델은 `gemini-3.5-flash-lite`이며, 서버는 각 항목의 앞뒤 공백을 제거한 길이가 10~300자인지 검사합니다.

## API 키와 데이터 보관

- Google AI Studio에서 발급한 키를 서버의 `GEMINI_API_KEY` 환경변수로 읽습니다. 키를 브라우저 코드, `localStorage`, Git 또는 화면에 저장하거나 표시하지 않습니다.
- 사용자의 브라우저와 이 서비스 서버 사이에는 해석 요청에 필요한 생년월일·출생시간이 전달됩니다. Gemini에는 위에서 정한 계산 결과만 전달됩니다.
- `localStorage` 기록에는 고유 ID, 저장 시각, 양력 생년월일, 출생시간, 계산 결과, 세 부분의 해석을 담습니다. 같은 입력으로 다시 성공하면 별도의 새 기록으로 남깁니다.
- `localStorage`는 현재 브라우저와 기기에만 남고 계정 간 동기화나 백업은 제공하지 않습니다. 같은 브라우저를 쓰는 다른 사람이 기록을 볼 수 있음을 저장 화면에 알립니다.
- 사용자는 저장된 기록을 개별 삭제할 수 있습니다. 삭제 후 목록과 화면에 해당 기록이 남지 않아야 합니다.

## 실패와 재시도

- 유효하지 않거나 지원하지 않는 생년월일·출생시간은 기존 입력 안내를 보여주고 Gemini를 호출하지 않습니다.
- API 키 누락, Gemini 요청 실패·시간 초과·사용량 제한, 응답 형식 오류는 각각 사용자에게 해석을 가져오지 못했다는 안내를 보여줍니다. 계산된 네 기둥은 그대로 유지하며, 가짜 해석을 만들거나 저장하지 않습니다.
- 실패 후 **다시 시도**할 수 있습니다. 재시도 성공 시에만 새 기록을 한 번 저장합니다.
- 브라우저 저장 공간 부족이나 저장 차단이 발생하면 해석은 화면에 보여주되, 저장되지 않았음을 분명히 알립니다.
- 기록을 읽을 때 손상된 데이터가 있으면 화면이 멈추지 않게 안내하고, 다른 정상 기록은 계속 볼 수 있어야 합니다.

## 범위 밖

- 로그인, 서버 데이터베이스, 다른 기기와의 동기화
- 결제와 전문가 상담 연결
- Gemini에 사주 계산을 맡기기
- 사용자가 자유 문장으로 질문하는 대화형 상담

## 완료 조건과 확인 사례

1. 정상 입력에서 기존 계산 결과가 먼저 보이고, 사용자가 버튼을 누른 뒤 세 부분의 해석이 보입니다.
2. 성공 결과 두 개를 저장하면 목록에 두 개가 보이며, 새로고침 후 각각 다시 열 수 있습니다.
3. 기록 하나를 삭제하면 그 기록만 사라지고 다른 기록은 남습니다.
4. API 키가 없거나 Gemini가 실패·잘못된 형식으로 응답하면 계산 결과는 유지되고 오류와 재시도 방법이 보이며, 실패 기록은 저장되지 않습니다.
5. 저장 실패 시 해석 내용은 읽을 수 있지만 저장 실패 안내가 보입니다.
6. 관련 자동 테스트와 실제 브라우저에서 성공·실패·재시도를 확인합니다.

## 현재 상태

화면, 서버 호출, 브라우저 결과 보관 기능을 구현하고 실제 Gemini 응답까지 확인했습니다. `docs/status.md`를 완료로 갱신했습니다.

## 구현 전 문서 정리

`docs/PRD.md`의 2단계 범위·결과·실패 조건을 이번 결정에 맞춰 갱신했습니다.

## 검증 결과 (2026-09-23)

- 최초 `npm run check` 통과: 타입 검사와 자동 테스트 31개 통과
- 자동 테스트에서 가상 Gemini 성공 응답, 실패·형식 오류·크레딧 소진, 여러 기록의 저장·재열기·삭제, 손상된 기록과 저장 실패를 확인했습니다.
- 실제 브라우저에서 실습용 입력 `2000-01-01 12:00`의 기존 사주 결과, 자세히 해석하기 버튼, 요청 중 표시, 실패 후 재시도 안내를 확인했습니다.
- 실제 Google 요청은 HTTP 402를 반환했습니다. 계정 잔액이 복구되면 실제 성공 결과, 새로고침 후 목록·다시 열기·개별 삭제를 화면에서 추가 확인해야 합니다.

## 재검증 결과 (2026-09-23)

- 사용자가 API 키를 변경한 뒤 Google의 간단한 시험 요청은 성공했습니다. 사주 해석 요청에서 일시적인 HTTP 503이 발생해 서버에 짧은 자동 재시도를 추가했습니다.
- 실제 Gemini 응답으로 실습용 입력 `2000-01-01 12:00`과 `2001-02-02 08:30`의 성향·강점·주의점 해석을 각각 확인했습니다.
- 같은 브라우저에 두 결과가 저장됐고, 새로고침 후에도 목록에 남았습니다. 첫 번째 기록을 다시 열어 입력값·네 기둥·해석이 복원되는 것을 확인했습니다.
- 개별 삭제는 자동 테스트에서 확인했습니다. 브라우저에서 만들어진 실습용 기록 두 건은 삭제하지 않고 남겨두었습니다.
- 최종 `npm run check` 통과: 타입 검사와 자동 테스트 33개 모두 통과.
