# 005: 사주 기반 로스트아크 세부 직업 추천

## 목적과 확정한 선택

사주 해석을 본 사용자가 로스트아크에서 시도해 볼 **세부 직업 한 개**와 그 이유를 재미있고 이해하기 쉬운 말로 확인하게 합니다. 사용자는 일반 RPG 역할군이 아닌 **로스트아크 직업**, 정해진 규칙이 아닌 **Gemini 추천**, **한 개만 추천**, **해석 기록과 함께 저장**을 선택했습니다.

이 결과는 오락용 제안입니다. 사주가 실제 성격·게임 실력·적성을 증명한다거나 특정 직업의 성능을 보장한다고 표현하지 않습니다. 로스트아크 공식 서비스가 제공하는 추천으로 오인되지 않게 표시합니다.

## 선행 조건과 화면 흐름

1. 기존 사주 계산과 기본 성향 한 문장은 로그인 없이 그대로 볼 수 있습니다.
2. 추천은 별도 자동 호출 없이, 로그인 사용자가 기존 **자세히 해석하기**를 눌렀을 때 성향·강점·주의점 해석과 함께 생성합니다. 비로그인 사용자는 기존처럼 로그인 안내를 봅니다.
3. 성공하면 기존 세 부분의 해석 아래에 **어울리는 로스트아크 직업** 한 개와 **추천 이유**를 표시합니다. 직업군 이름만 표시하거나 여러 직업을 나열하지 않습니다.
4. 해석과 추천은 같은 계정 기록 한 건으로 저장됩니다. 목록에서 다시 열거나 새로고침·다른 기기에서 열어도 저장 당시의 직업과 이유를 그대로 보여줍니다. 다시 열 때 Gemini를 재호출하지 않습니다.
5. 기존 브라우저 `localStorage` 기록과 이 기능 도입 전 데이터베이스 기록에는 추천을 억지로 채우거나 자동 생성하지 않습니다. 해당 기록은 기존 해석만 보여주고, 추천이 없는 과거 기록임을 표시합니다. 사용자가 새 해석을 명시적으로 요청하면 새 기록과 새 추천을 만들 수 있습니다.
6. 입력을 바꾸거나 새 사주를 계산하거나 로그아웃하면 화면에 남은 이전 추천을 지워 다른 사람/사주의 결과처럼 보이지 않게 합니다. 기록을 삭제하면 추천도 함께 삭제됩니다.

### 직업별 생성 이미지

- 자세한 해석 요청이 성공해 추천 직업이 표시되면, 그 직업에 대응하는 **기존 생성 이미지 한 장의 해당 캐릭터 영역**을 추천 카드에 함께 보여줍니다. 저장된 계정 기록을 다시 열 때도 저장 당시 직업명으로 같은 이미지를 보여줍니다. 추천이 없는 과거 기록에는 이미지를 보여주지 않습니다.
- 사용자가 이미 만든 `output/lostark-sd-details-2026-09-23-v01/`의 직업군별 합성 이미지 6장을 원본으로 사용합니다. 원본은 변경하지 않고 웹 공개 자산에 복사합니다. 각 이미지의 직업별 캐릭터 위치를 코드에서 명시적으로 연결하며, 제목과 다른 직업 캐릭터가 섞여 보이지 않도록 화면에서 해당 영역만 잘라 보여줍니다. 30개 허용 직업 각각에 정확히 한 영역을 연결합니다.
- 추천 생성·저장은 기존 `recommended_class`와 `recommendation_reason`만 사용합니다. 이미지 자체나 경로를 데이터베이스에 새로 저장하지 않고, 화면에서 직업명으로 이미지를 찾습니다. 알 수 없는 직업명 또는 이미지 로딩 문제로 해석·기록을 실패 처리하지 않으며 텍스트 추천을 유지합니다.
- 이미지에 직업명을 포함한 대체 설명을 제공하고, 생성 이미지이며 로스트아크 공식 아트가 아니라는 안내를 표시합니다. 작은 화면에서도 이미지 비율과 캐릭터가 유지되어야 합니다. 공식 로고나 게임 제공 이미지를 가져오지 않습니다.

## 추천 생성 기준

- 서버는 기존 `lib/saju`로 사주를 다시 계산하고, 계산된 네 기둥·일간·오행과 초보자용 해석 지침을 Gemini에 전달합니다. 원래 생년월일·출생시간, 계정 식별자, 인증 토큰은 Gemini에 보내지 않습니다. Gemini에게 사주 계산을 맡기지 않습니다.
- 기존 해석 생성 요청 하나에서 `personality`, `strengths`, `cautions`와 함께 `recommended_class`, `recommendation_reason`을 받습니다. 추천을 위한 별도 자동 API 호출은 만들지 않습니다. 이유는 사주에서 사용한 특성과 해당 직업의 **공식 소개에 확인되는 플레이 특징**을 연결한 쉬운 한국어 1~2문장으로 작성하도록 요청합니다. 성별·연령·출생 연도 자체를 적합성 판단 근거로 삼지 않습니다.
- 추천 대상은 구현 시점의 [로스트아크 공식 클래스 소개](https://lostark.game.onstove.com/Class)에서 확인한 **현재 플레이 가능한 세부 직업**입니다. 공식 소개에서 확인한 직업명과 간단한 특징을 서버의 버전 관리되는 허용 목록으로 유지하고 Gemini에는 그 목록만 후보로 제공합니다. 공식 사이트의 목록이 동적으로 표시될 수 있으므로 구현 전에 화면에서 직업명·특징을 직접 재확인하고, 추가·개명·삭제된 직업은 목록을 갱신합니다. 요청마다 외부 사이트를 긁어오거나 Gemini가 새 직업명을 만들어내게 하지 않습니다.
- 서버는 응답 구조, 문자열 앞뒤 공백, 직업명이 허용 목록에 정확히 있는지, 이유가 빈 문장/과도하게 긴 문장인지 검사합니다. 이유의 구체적인 허용 길이는 구현 전 기존 세 해석 항목의 10~300자 기준과 일관되게 정합니다. 허용 목록 밖 직업, 존재하지 않는 스킬·성능 주장, 추천 직업과 무관한 이유는 성공으로 처리하지 않습니다.
- 같은 사주라도 새 해석 요청에서는 Gemini 결과가 달라질 수 있습니다. 같은 요청의 네트워크 재시도에는 기존 `request_id`를 사용해 저장된 추천을 그대로 반환하며 중복 생성하지 않습니다.

## 저장과 접근 제어

- 기존 `public.saju_interpretations`에 `recommended_class`, `recommendation_reason`을 저장하는 **새 migration**을 만듭니다. 이전 기록이 존재하므로 두 열은 과거 행에서 `NULL`을 허용하고, 새 요청의 두 값은 서버가 모두 필수로 검사합니다. 데이터베이스에는 둘 다 있거나 둘 다 없는 상태만 허용하는 제약을 둡니다. 과거 행을 임의의 추천값으로 채우지 않습니다.
- 성향·강점·주의점·추천 직업·이유는 한 행에 함께 저장합니다. 한 부분만 성공한 기록을 새로 만들지 않습니다. 목록·상세 조회 API와 서버/브라우저 형식 검사는 이전 행의 추천 없음과 새 행의 추천 있음을 모두 안전하게 처리합니다.
- 계정별 접근은 004 Spec의 세션 검증과 RLS(각 사용자가 자기 행만 볼 수 있게 하는 데이터베이스 규칙)를 그대로 적용합니다. 브라우저가 보낸 직업명·추천 이유·사용자 ID는 저장 근거로 신뢰하지 않습니다. 추천을 `localStorage`에 새로 저장하지 않으며 예전 브라우저 기록도 변경하지 않습니다.
- 저장된 직업명은 당시 결과의 기록이므로 이후 로스트아크 직업 목록이 바뀌어도 과거 기록의 이름·이유를 조용히 다시 쓰지 않습니다.

## 실패와 재시도

- 비로그인·만료 세션, 유효하지 않은 입력은 Gemini 호출 전에 거부하고 기존 안내를 보여줍니다.
- Gemini 호출 실패·시간 초과·사용량 제한, 해석 또는 추천의 형식 오류, 허용 목록 밖 직업이 나오면 새 해석/추천을 성공처럼 표시하거나 데이터베이스에 저장하지 않습니다. 이미 계산된 사주 네 기둥과 기본 성향은 유지하고 실패 안내와 **다시 시도**를 보여줍니다. 가짜 직업이나 임의의 기본 추천으로 대체하지 않습니다.
- Gemini 결과는 정상인데 데이터베이스 저장에 실패하면 해석과 추천을 현재 화면에만 보여주고 **계정에 저장되지 않았음**을 명확히 알립니다. 기록 목록에는 성공처럼 추가하지 않습니다. 재시도 때 동일 `request_id`의 저장 여부를 먼저 확인하는 004 Spec의 중복 방지 원칙을 유지합니다.
- 과거 기록에 추천이 없어도 기록 열람은 실패가 아닙니다. 추천 영역에 “이전 기록에는 직업 추천이 없습니다”처럼 안내합니다.

## 이번 범위에서 제외

- 여러 직업 추천, 직업 순위·점수·승률·메타 성능 평가, 특정 각인·스킬트리·장비 추천
- 사용자 취향·조작 난도·파티 선호를 묻는 추가 설문이나 성별/연령 기반 추천
- 게임 계정 연동, 캐릭터 생성, 로스트아크 API 호출, 공식 직업 이미지·로고 복제
- 과거 결과에 대한 자동 추천 생성·일괄 재저장, 기존 브라우저 기록의 계정 이전

## 완료 조건과 검증 사례

1. 로그인 후 유효한 사주를 계산하고 **자세히 해석하기**를 누르면 세 해석 항목과 허용 목록에 있는 세부 직업 **정확히 한 개**, 사주 특성과 직업 특징을 잇는 쉬운 이유가 보입니다. 추천의 오락용 성격도 안내합니다.
2. 새 결과가 한 행에 저장되고, 새로고침·재로그인·다른 기기에서 열어도 같은 직업과 이유가 보입니다. 삭제하면 해당 추천도 사라집니다.
3. 과거 DB/브라우저 기록은 그대로 열리며 추천 없음 안내가 보입니다. 자동으로 새 추천이나 DB 행이 생성되지 않습니다.
4. 모델이 허용 목록 밖 직업·빈 이유·잘못된 구조를 반환하면 저장되지 않고 오류·재시도가 표시됩니다. 비로그인 요청은 Gemini 호출 없이 거부됩니다.
5. 같은 `request_id` 재전송은 Gemini를 다시 호출하거나 행을 중복 생성하지 않습니다. 사용자 A/B의 추천 기록은 기존 RLS 정책에 따라 분리됩니다.
6. 타입 검사·자동 테스트와 실제 화면에서 정상 생성, 저장·재열기, 이전 기록, 오류·재시도, 로그아웃 후 표시 제거를 확인한 뒤에만 `docs/status.md`를 완료로 바꿉니다.
7. 추천한 30개 직업 모두 해당 생성 이미지의 캐릭터 영역으로 연결됩니다. 자세한 해석 성공과 계정 기록 재열기에는 이미지가 보이고, 추천 없는 과거 기록에는 이미지가 없습니다. 모바일 크기와 대체 설명도 확인합니다.

## 현재 상태

로컬 코드와 새 SQL migration을 작성했습니다. 공식 클래스 페이지를 기준으로 확인한 직업 30종을 서버 허용 목록으로 두고, Gemini 응답의 직업·이유 형식 검사, 계정 기록 저장·재열기, 화면 표시를 연결했습니다. 과거 기록은 추천 없음으로 계속 열립니다.
